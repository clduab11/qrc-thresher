# Audit 2026-09: state of qrc-thresher at the end of the September refactor

**Branch:** the September refactor branch, from `main` at 27dfcd4. **HEAD of record:** 8ed2df4 for
the evidence (run 4); the CP5 commits follow it. It cites commits and decisions
(`docs/DECISIONS.md`, append-only apart from the one ruled edit D017 records, D001–D020) and names
modules and functions; it uses no line anchor from before the refactor. Where a decision or an item
is written "(builder)" it was proposed by the builder and accepted by the PI; every scientific and
scope decision was the PI's.

## 1. Status at HEAD

- **Reservoir.** The default QRC is the windowed reservoir of D010 (`reservoirs/windowed_qrc.py`; at
  w = 1 it is the memoryless control; design (a): qubit $j$ re-uploads $u_{t-(j \bmod w)}$ at every
  layer through $R_y(\alpha u)$); the window $w$ and encoding scale $\alpha$ are tuned
  hyperparameters (D011). `reservoirs/pennylane_qrc.py` is the frozen $w = 1$, $\alpha = \pi$
  reference. A reservoir with carried quantum state (design (b)) is not built (D003).
  `reservoirs/smoothed_qrc.py` is classical smoothing of the exact features and is reported as such
  (D018); `reservoirs/stateful_qrc.py` is its deprecated alias.
- **Measurement.** Exact expectation values only, labelled "exact (oracle upper bound)" (D004);
  classical arms are labelled "classical, no measurement cost" (D018). Finite-shot measurement is not
  built; D004's commitment that it lands before any comparative sweep was not met by run 4 and is
  open (D017 ledger, CP5a ruling 1).
- **Baselines.** A dense numpy ESN with one draw per seed, an input bias and block validation
  (D009, D011, `baselines/esn.py`); windowed random kitchen sinks with bandwidth $\sigma/\sqrt{d}$
  (D011, `baselines/random_features.py`); both tuned under the QRC's 60-configuration budget by one
  tuner (`tuning.py`). The GRU stub is dropped (D018). Matched ablations `phase_random`, `no_entangle`
  and `haar` live in `reservoirs/windowed_qrc.py` (D010).
- **Gates.** G0.7 v1 (`configs/gates/G0.7.v1.yaml`; D005, D008; `gates/g07.py`); the registered
  family COMPARATIVE.v1 of G1, G2, G2.5, G3 and G4 (`configs/gates/COMPARATIVE.v1.yaml`; D013, D014;
  `gates/comparative.py`, `metrics/paired.py`); G0.5 on 34 registered cases at one tolerance (D010,
  D011; `commands/gate.py`). Every gate file written after D018 is timestamped and never overwritten,
  and carries its commit (`git_commit_hash`; the family record and its views keep `git_commit`,
  D018), its `config_hash` (or null with a reason) and, wherever a reservoir is evaluated, the
  measurement label; run 4's G0.7 file predates D018 and records its commit in `environment` and its
  config in `model_details.tuning_config_hash`.
- **Provenance.** Manifest schema 1.4 (`proof/run_manifest.py`; D004, D013). One runs.csv reader
  with a pinned parse (`gates/comparative.read_runs_csv`, D019). Evidence export and scorecard
  (`proof/evidence.py`, `proof/scorecard.py`; D019, ruling P4).
- **Run 4** (commit 8ed2df4, sweep 20260924T214530147999Z, config
  `configs/comparative.yaml`, 12 seed pairs; every row of that config and sweep, the count being the
  family record's top-level `n_rows`) is the registered CP4 evidence (D019):
  G1 FAIL, G2 PASS, G2.5 FAIL, G3 FAIL, G4 FAIL. Every statistic is read from the files under
  `docs/evidence/8ed2df4/` and rendered in `docs/scorecard.md`; none is restated here.
- **Suite.** 438 passed and 2 `slow` deselected at 8ed2df4; CP5a added the CP5 tests red (24f1a2a).
  At f95ab3d, the last CP5b code commit, only the tests that read the files of the docs and
  evidence commits were red; at the evidence commit 589 passed and 2 `slow` deselected on the
  reference platform (D020). Ruff is clean at 8ed2df4 and at every CP5 commit.

## 5. Reproduction

Install from the lock and run the suite (Python 3.11–3.13):

```bash
uv sync --locked
uv run pytest -q
```

On any platform other than run 4's reference platform the re-derivation tests fail with a message
naming D020; the hash tests run everywhere.

Run 4's rows and records are produced by the CP4c sequence on a checkout of 8ed2df4 with an empty
`results/` (archive first):

```bash
qrc-thresher tune --config configs/comparative.yaml
qrc-thresher run stm --config configs/comparative.yaml
qrc-thresher run parity --config configs/comparative.yaml
qrc-thresher run narma --config configs/comparative.yaml
qrc-thresher run parity --config configs/comparative.yaml --design-task stm
qrc-thresher run stm --config configs/comparative.yaml --design default
qrc-thresher run parity --config configs/comparative.yaml --design default
qrc-thresher run narma --config configs/comparative.yaml --design default
qrc-thresher ablation no_entangle stm --config configs/comparative.yaml
qrc-thresher ablation no_entangle parity --config configs/comparative.yaml --design-task stm
qrc-thresher ablation no_entangle stm --config configs/comparative.yaml --design default
qrc-thresher ablation no_entangle parity --config configs/comparative.yaml --design default
qrc-thresher ablation haar stm --config configs/comparative.yaml
qrc-thresher ablation haar stm --config configs/comparative.yaml --design default
qrc-thresher baseline stm --config configs/comparative.yaml
qrc-thresher baseline stm --config configs/comparative.yaml --design default
qrc-thresher baseline parity --config configs/comparative.yaml
qrc-thresher baseline parity --config configs/comparative.yaml --design default
qrc-thresher baseline narma --config configs/comparative.yaml
qrc-thresher baseline narma --config configs/comparative.yaml --design default
qrc-thresher gate G0.7 --config configs/alpha_lite.yaml --model tuned_qrc --tuning-config configs/comparative.yaml
qrc-thresher gate family --config configs/comparative.yaml
```

(D019's sequence without its final `summary --phase cp4c`, which only writes results/summaries/.)

A reproduction is compared, from a CP5 checkout, with the evidence and not with this document:

- the family's `protocol_sha256` and `config_hash`;
- each member's verdicts, p-values, statistics, means and n;
- the tuning records' selected design per seed pair (depth, window, encoding scale, `circuit_hash`).

Fields that differ by construction: `timestamp_utc`, `git_commit`/`git_commit_hash`, `run_id`,
`sweep_id`, `tuning_record_sha`, the records' `record_sha256` (it hashes the record's own sweep id)
and the G0.7 path and sha in `members.G1.g07`. Off the reference platform the Haar circuit hashes
and the last digits of some p-values also differ (D020). Export a reproduction only to a scratch
folder (`--out-root <scratch>`), never into `docs/evidence/8ed2df4/`, which the export refuses to
overwrite.

To export and render a run made at a post-CP5 commit:

```bash
qrc-thresher evidence results/gates/COMPARATIVE.v1.<stamp>.json --config configs/comparative.yaml --runs-csv results/runs.csv
qrc-thresher scorecard   # every evidence folder; default output docs/scorecard.md
```

The export refuses an unknown or `-dirty` commit, a planted path or a forbidden key, and never
overwrites an evidence folder (`proof/evidence.py`; D019, ruling P4).
